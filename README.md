# 底层规律运用

简体中文 | [English](README.en.md)

**用有证据、有边界的跨学科模型，把真实问题转化为可比较的选择和可检验的下一步。**

`apply-underlying-principles` 是面向工作、商业、学习与生活决策的 AI Skill。它将知识整理为带有来源、适用条件和误用警示的模型卡，并规定如何把这些模型用于具体问题。

它关注的不是“知道多少概念”，而是：**你凭什么做出这个判断？什么情况下它不成立？下一步怎样降低不确定性？**

当前知识库包含 **31 张模型卡、4 个主题领域、3 种使用模式**。这是一个由指令和参考资料组成的 Skill，不是独立运行的应用，也不是经过实证验证的收益或幸福感提升工具。

## 可以用它分析什么？

| 领域 | 你可能正在面对的问题 | 代表模型 | 卡片数 |
| --- | --- | --- | --- |
| 认知、证据与系统 | 为什么指标变好了，实际结果却变差？项目为什么越忙越慢？ | 基准率、因果推断、校准、反馈、瓶颈、在制量与周期时间 | 14 |
| 赚钱、商业与职业 | 要不要扩张、转行、涨价或接受一个高风险机会？ | 机会成本、比较优势、激励、单位经济、杠杆与流动性 | 8 |
| 工作与学习 | 为什么学过却不会用？怎样判断效率问题出在哪？ | 任务切换、间隔与提取练习、学习支架、反馈、习惯线索 | 5 |
| 关系与福祉 | 谈判如何准备？对方需要建议还是支持？目标之间怎样取舍？ | 谈判替代方案、关系回应性、自主与胜任需要、睡眠与活动的健康边界 | 4 |

更适合的问题通常有几个特征：信息不完整、目标有冲突、资源有限，或者选错的代价不低。它也可以解释一个概念，但不以罗列知识作为分析的终点。

### 2. 带着真实问题调用

```text
用 $apply-underlying-principles 分析下面的问题：

问题：[我现在需要做的判断]
目标：[希望改变什么，怎样算有效]
已知事实：[数据、观察、已经尝试过的方法]
备选方案：[目前考虑的选择，包括维持现状]
重要约束：[时间、预算、健康、关系、不能承受的损失]
不确定之处：[哪些信息还不知道]

请先给核心判断，再区分事实、推断和未知；
说明关键模型为什么适用，以及什么证据会改变结论。

```

不必为了填满模板而编造数据。不知道的信息直接写“不知道”，真实约束比完整表格更重要。

## 它怎样分析一个问题？

完整规则见 [SKILL.md](SKILL.md)。默认分析按以下顺序展开：

1. **定义问题。**明确目标、可观察的成功标准、时间范围，以及谁做决定、谁承担后果。
2. **识别结构与基线。**检查约束、瓶颈、激励、反馈延迟和失败成本；寻找可比案例，并把维持现状纳入比较。
3. **选择 3–7 个相关模型。**只选能改变诊断或选择的模型，说明它在这里预测什么、边界是什么。
4. **交叉检查并比较方案。**检查模型冲突、替代解释、二阶后果、指标失真和极端损失，不把偏好偷偷当成事实。
5. **设计下一步。**在适合试验时，明确基线或对照、一个主要指标、反馈窗口，以及事先约定的继续或停止条件。
6. **保留修正入口。**区分事实、推断与未知，说明置信程度，以及哪些新证据会推翻或缩小结论。

最终回答先给核心判断，再按需要展开。不是每个问题都需要长报告，也不是每个决定都适合做实验：涉及不安全、不道德、不可逆或缺乏信息价值的试验时，应选择其他验证方式或暂缓建议。

## 专业性来自哪些约束？

### “底层规律”不是无条件成立的真理

这里的“规律”包括数学关系、条件性理论模型和有不同程度经验支持的机制。三者不能互相替代：

- 公式推导正确，不代表输入准确或现实满足模型假设。
- 机制讲得通，不代表因果关系已经得到验证。
- 群体平均有效，不代表对当前这个人、团队或时期同样有效。

因此，模型卡同时记录“何时使用”和“何时不要使用”。边界不是附带免责声明，而是选择模型和行动的一部分。

### 证据、因果与收录状态分别判断

知识库采用以下证据标记。它们是项目内部的知识筛选与审核规则，不是外部认证，也不是从弱到强的一条简单排名。

| 标记 | 表示什么 | 使用约束 |
| --- | --- | --- |
| `T` | 理论推导、恒等式、证明或正式定义 | 先核对假设；不能据此证明现实效果 |
| `A` | 较强且一致的经验支持 | 不等于效果大、没有差异或普遍适用 |
| `B` | 可信但有边界的经验支持 | 核对人群、场景、干预、比较对象、结果和时间范围 |
| `C` | 初步、间接或高度依赖情境的支持 | 未经用户具体情境验证，不得主导建议 |
| `X` | 不应据此行动的命题 | 只能作为误用警示，不能支持建议 |

因果解释另标为 `causal`、`probable-causal`、`associational` 或 `theoretical`。例如，高质量的关联证据仍然不能直接证明干预有效。

是否收录又是第三个判断：`core`、`conditional`、`watchlist`、`reject`。审查同时考虑清晰度、证据强度、因果有效性、外部适用性、决策相关性、判断错误的危害，以及是否已有更简单的模型覆盖同一问题。[完整证据与模型卡标准](references/evidence-and-card-standard.md)

### 多模型分析不是“多数投票”

模型之间可能是补充关系，也可能存在优先约束。某个方案的预期收益更高，不能自动越过不可承受的损失底线；等待可以保留选择权，也可能带来机会成本。分析要解释这些关系，而不只是把每个模型分别讲一遍。

同样，收入、健康、自主、关系与稳定之间的权重属于决策者。Skill 应把取舍说清楚，而不是替你规定什么样的人生才算成功。

## 一个例子：为什么客服结单更多，重复投诉却上升？

以下是**虚构的分析示例**，用于展示方法，不是实际部署结果。

**问题：**“我们考核客服结单量。最近结单量上涨，重复投诉也上涨，是否应该继续提高结单目标？”

一个有价值的初步判断是：先确认客户问题是否真正解决，再决定是否加大现有指标的激励。

| 分析视角 | 它改变了什么判断？ | 还需要核实什么？ |
| --- | --- | --- |
| 多任务激励 `M06` | 在模型条件成立时，追求易测的结单量可能挤占难测的解决质量 | 奖励规则、客服时间分配，以及结单量和质量是否存在实际冲突 |
| 代理指标失效 `E07`、局部与全局优化 `S05` | 提供“数字改善但整体结果恶化”的候选解释 | 两张卡均为 `C` 级，不能仅凭现象就认定员工刷指标 |
| 因果辨析 `E03` | 同时考虑产品故障、客户结构变化、记录口径改变等竞争解释 | 哪种解释与问题发生的时间、群体和流程最吻合 |

**下一步：**先按问题类型和难度抽样追踪完整处理链路，检查结单与后续重复联系的关系。如果本地证据支持激励错配，再考虑经授权的小范围试点，并保留可比基线或对照。

试点可以把“同一问题的重复联系率”作为主要结果，把响应时间和员工负荷作为护栏。观察窗口和停止阈值应根据真实处理周期与现有基线事先确定，而不是套用一个看似精确的天数或百分比。

如果数据更支持产品故障或统计口径变化，应相应改变诊断；即使试点指标改善，也要检查同时发生的其他变化，不能立刻宣称因果已被证明。

## 三种使用模式

| 模式 | 用途 | 示例请求 |
| --- | --- | --- |
| 应用 `Application`，默认 | 分析真实问题，比较方案并提出下一步 | “用这个 Skill 分析是否应该把副业转成全职。” |
| 解释 `Explanation` | 理解概念、机制、条件、反例和误用 | “用这个 Skill 解释均值回归，以及它不能证明什么。” |
| 审查 `Audit` | 判断一个候选规律是否值得收录 | “用这个 Skill 的 Audit 模式审查‘21 天一定能养成习惯’，按七项标准判断，给出一个收录结论。” |

审查模式不会自动改写知识库。只有用户明确要求更新时，才应修改资料。

## 验证状态与能力边界

v1 包含 12 个用于开发改进的评估场景。开发记录描述了自评、交叉评分和修订后的复测；这些用于发现问题和设定发布门槛，**不是盲测，也不是 Skill 优于普通回答或改善真实决策结果的因果证据**。部分评估复用了已有项目上下文的代理，泛化能力仍需更多独立案例检验。

使用时还需注意：

- **当前是精选知识库，不是完整学科体系。**核心模型卡正文主要为中文；英文 README 不代表知识库已完整英译。
- **资料不会自动保持最新。**现有模型卡标注的审阅日期为 2026-09-04，后续结论应随新证据调整。
- **高风险与时效性问题需要当时查证。**医疗、法律、投资及安全相关判断，应核对当前权威来源；无法取得必要证据时，应缩小、暂缓或省略建议。
- **Skill 是行为约束，不是正确性保证。**输出仍取决于所用模型、输入质量、工具权限和执行情况；它不提供个人医疗或心理诊断、收益承诺或对他人动机的确定判断。
- **反馈不等于自动学习。**一次成功不能证明模型有效，一次失败也不必然否定模型；需要检查假设、执行、测量和情境，并明确决定是否修订。

## 如何贡献

欢迎提交候选模型、来源纠错或脱敏后的真实案例。优先提供：

1. 想提出或纠正的准确命题，以及直接支持它的来源。
2. 适用条件、反例、竞争解释，以及判断错误可能造成的危害。
3. 对真实案例，补充事前目标、已知信息、选择理由和后续结果，避免只用事后成败评判过程。

请按[模型卡标准](references/evidence-and-card-standard.md)讨论收录，不用知名度或直觉替代证据；也不要提交个人隐私、客户资料或商业机密。

**一个好的分析，不仅说明现在为什么这样判断，也说明未来应当在什么条件下改变判断。**
